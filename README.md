# Disclosure Ledger

**Private proof-of-prior-discovery for security researchers, built on [Midnight](https://midnight.network).**

Bug-bounty programs lose researchers over one recurring fight: *"duplicate, someone reported it first."*
The researcher cannot prove when they found the bug without publishing it, and publishing an
unfixed vulnerability is the one thing they must not do.

Disclosure Ledger fixes that with Midnight's dual public/private ledger:

1. **Commit privately.** A researcher commits to a report. The public ledger stores only a
   commitment, a pseudonymous owner key, a global ordinal and an on-chain-enforced time bound.
   The report, its hash and the researcher's identity stay in private state on their machine.
2. **Prove to one vendor, privately.** The researcher sends the vendor the report and its salt. The
   vendor recomputes the commitment locally and reads the entry: *"this exact report was on chain
   before 2026-11-04T21:10Z, as entry #17"*. Nothing is written on chain and nobody else learns
   that the check happened.
3. **Disclose selectively, on chain.** When the researcher chooses, a zero-knowledge proof shows that
   their entry opens to the SHA-256 digest the vendor published, without revealing the salt or the
   report. Only the owner can do this, and later mark the entry resolved or withdraw it.

The result: priority disputes are settled by a public, tamper-proof order of commitments, while
the vulnerability itself stays secret until the vendor has fixed it.

with toolchain 0.36.0 (language 0.28) as a forward-compatibility check, so the move to ledger 9 is a
version bump.

## Setup

Prerequisites: Node.js 20+, and the Compact devtools on Linux or macOS
(on Windows use WSL, or let CI compile for you).

```sh
# 1. Compact compiler
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/midnightntwrk/compact/releases/download/compact-v0.5.3/compact-installer.sh | sh
compact update 0.31.1

# 2. Dependencies
npm ci --legacy-peer-deps

# 3. Compile the contract (writes contract/src/managed/disclosure-ledger: JS bindings, ZKIR, prover/verifier keys)
npm run compact

# 4. Tests (vitest, simulator)
npm test

# 5. End-to-end demo in the terminal
npm run build
npm run demo
```

CLI tools (after `npm run build`):

```sh
npx tsx cli/src/index.ts digest ./my-report.md                  # SHA-256 of a report (what a vendor computes)
npx tsx cli/src/index.ts commitment <digestHex> <saltHex>       # the public commitment for an opening
```

## The contract

### Public ledger (visible to everyone)

```compact
export ledger entries: Map<Bytes<32>, Entry>;   // keyed by commitment
export ledger entryCount: Counter;

export struct Entry {
  owner: Bytes<32>,      // persistentHash(domain, commitment, secretKey)
  ordinal: Uint<64>,     // 1-based global order of commitments
  notAfter: Uint<64>,    // UNIX seconds; the commit tx asserted blockTimeLt(notAfter)
  status: Status,        // committed | disclosed | resolved | withdrawn
  digest: Bytes<32>      // zero until the owner proves the match to a vendor digest
}
```

### Private state (witnesses, never leaves the researcher's machine)

```compact
witness localSecretKey(): Bytes<32>;                       // long-term researcher secret
witness draftReport(): ReportOpening;                      // { digest, salt } being committed
witness reportOpening(commitment: Bytes<32>): ReportOpening; // opening of an earlier commitment
```

The TypeScript side (`contract/src/witnesses.ts`) keeps
`{ secretKey, draft, reports: { [commitmentHex]: { digest, salt } } }`. The `draftReport` witness
both hands the draft to the circuit and files it under the commitment it will produce, so private
state stays consistent with the public ledger. The update is only kept if the transaction succeeds.

### Circuits

| Circuit | Who | What becomes public | Checks (in zero knowledge) |
|---|---|---|---|
| `commitReport(notAfter)` | anyone | commitment, owner key, ordinal, `notAfter` | block time < `notAfter`; commitment = `persistentCommit(digest, salt)` from private draft; not already committed |
| `proveMatch(commitment, vendorDigest)` | owner | status `disclosed`, `vendorDigest` | caller's secret key derives the entry's owner key; private opening matches the commitment; opening's digest equals `vendorDigest` |
| `markResolved(commitment)` | owner | status `resolved` | ownership; entry is `disclosed` |
| `withdraw(commitment)` | owner | status `withdrawn` | ownership; entry is `committed` |
| `reportCommitment(digest, salt)` | pure | none | shared with TypeScript so vendors hash identically |
| `ownerKey(sk, commitment)` | pure | none | |

## Privacy design: what is public, what is private, and why

| Data | Where | Why |
|---|---|---|
| Report text | researcher's disk only | it is an unfixed vulnerability |
| `digest = sha256(report)` | private state; public only after `proveMatch`, and only the vendor can link it to text | lets a vendor check with standard tools, but a bare hash reveals nothing |
| `salt` (32 random bytes) | private state, or handed to one vendor | blinds the commitment, so even someone who guesses the report cannot confirm the guess |
| commitment | public | the anchor that proves existence, order and time |
| secret key | private state | proves ownership in ZK |
| owner key | public | `hash(domain, commitment, sk)`: different per entry, so an observer cannot link a researcher's entries or count how many bugs they found |
| `notAfter`, ordinal | public | the whole point: provable priority |

Design notes:

- **Time is enforced by the network, not claimed.** A circuit cannot read the clock, but it can assert
  `blockTimeLt(notAfter)`; the ledger rejects the transaction if the block is too late. A researcher
  picks `notAfter = now + a few minutes`, and the ordinal breaks ties inside that window.
- **Commitments, not hashes.** `persistentCommit` with a random salt hides the digest; Compact's
  disclosure analysis treats it as safe to publish. The owner key is a `persistentHash` of witness data,
  so it is wrapped in an explicit `disclose()`, and so are circuit arguments written to the ledger.
- **Ownership without identity.** Owner-only circuits re-derive the owner key from the witness secret
  inside the proof (the pattern from Midnight's bboard example), so the secret key never appears in a
  transaction.
- **Stolen openings are useless on chain.** Someone who obtains a report and salt can verify it, but cannot
  disclose, resolve or withdraw the entry: the tests cover exactly this case.

## Tests

`npm test` runs the vitest suite in `contract/src/test/` against the compiled contract through
the simulator, which runs the circuits with `@midnight-ntwrk/compact-runtime` exactly as a DApp
does before proving, with in-memory ledger state, a settable block time and several researchers
with separate private state. It covers commit, deadline enforcement, duplicate refusal,
TypeScript/circuit hash agreement, private-state updates, unlinkable owner keys, selective
disclosure (correct digest, wrong digest, non-owner with stolen opening, tampered private
opening), the status lifecycle, vendor verification and duplicate-dispute ordering.

## Roadmap

- Web UI wired to the contract (Lace wallet + proof server via midnight-js), deployed on Preprod.
- Vendor-scoped disclosure: prove a match to one vendor's public key without publishing the digest.
- Optional researcher reputation: prove "I own N resolved entries" without linking them.
- Bounty-platform integration: a platform checks priority before marking a report duplicate.
